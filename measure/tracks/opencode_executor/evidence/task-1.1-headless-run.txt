# Task 1.1 — Headless run contract

All container runs in this task use rootless Podman with
`--pull=never`, the harness's pinned image digest
(`docker.io/library/node@sha256:6c74791e557ce11fc957704f6d4fe134a7bc8d6f5ca4403205b2966bd488f6b3`),
the opencode binary bind-mounted read-only at `/usr/local/bin/opencode`,
and ripgrep bind-mounted read-only at `/usr/local/bin/rg` (FR-4 helper
supply method, see evidence/task-1.7-container-runtime.txt).
HOME + XDG are private tmpfs paths. No host home, no host dotfile tree,
and no host credential store is mounted. The generated config
(see "Generated config" below) is bind-mounted at
`/tmp/config/opencode/opencode.json` and selected through
`OPENCODE_CONFIG`.

## 1. Generated config

The container uses a generated `opencode.json` that sets the default
model and applies the FR-4 permission contract: `deny skill *`,
`deny question *`, `deny websearch *` (O2). It contains no secret.

```json
{
  "$schema": "https://opencode.ai/config.json",
  "model": "opencode-go/beam-free",
  "permissions": [
    { "action": "skill", "resource": "*", "effect": "deny" },
    { "action": "question", "resource": "*", "effect": "deny" },
    { "action": "websearch", "resource": "*", "effect": "deny" }
  ]
}
```

## 3. Live prompt 1 (slirp4netns)

```
$ timeout 90 podman run --rm --pull=never \
    --network=slirp4netns:allow_host_loopback=false \
    --mount ... <container setup> \
    /bin/sh -c "opencode auth import /tmp/cred.json && \
                echo '=== run ===' && \
                timeout 60 opencode run --standalone --format json --auto \
                       --model opencode-go/beam-free 'Reply with the word OK.' </dev/null"
rc=0
stdout: 631 bytes
stderr: 22 bytes ("Imported 1 credential")
```

The full redacted event stream is in
`evidence/live1-event-stream.redacted.json` (500 bytes, 2 events).

### 3.1 Flags work

All five spec flags worked:
- `--standalone`: opencode started a private server (no host
  service connection was needed).
- `--format json`: stdout is NDJSON, one event per line.
- `--auto`: no permission prompt. The default `build` agent's
  permission for `question` is `ask` per the host's
  `opencode debug agents` output, but the config's
  `permissions: [{action:"question", resource:"*", effect:"deny"}]`
  makes the `question` action `deny` so it is never asked.
- `--model opencode-go/beam-free`: the model was selected
  (prompt 1 was answered with "OK" by `opencode-go/beam-free`).
- `--auto` left no permission prompt: no `question` event was
  emitted. The model responded directly with `text` event "OK".

### 3.2 Stdin behavior

`stdin` was redirected from `/dev/null`. The run consumed 0 bytes
of stdin (the model was not asked to read files; no `read` tool
call was made). The prompt was passed as a command-line argument,
not through stdin.

### 3.3 JSON event types

For prompt 1 (`Reply with the word OK.`):
- `step_start` (beginning of an agent step)
- `text` (model output: "OK")
- (no `step_finish` because the response was so short the
  harness may have not recorded a finish event for this
  minimal exchange; the O3 probe in task 1.8 shows the full
  event sequence including `step_finish`)

### 3.4 Exit code

rc=0 from the container. The model call completed successfully.

### 3.5 Import with inert refresh

Import succeeded with rc=0 and stderr "Imported 1 credential".
The import wrote to the container's isolated store (no host
store was touched; host auth.json is byte-identical, see
section 4 below).

The inert refresh (`"refresh": "inert"`) was accepted by the
import subcommand. It would only matter when the model endpoint
needs to use the refresh token to renew an expired access token.
For this prompt, the access token has not expired, so the refresh
field was not exercised.

## 5. Addendum to task 1.3 evidence

This run confirms the access-only copy works end-to-end:
the container's `opencode auth import` accepted the
`refresh="inert"` JSON, wrote it to the isolated store, and the
subsequent `opencode run --standalone` used the stored access
token to reach the model endpoint and receive a reply. The
inert refresh was not exercised (the access token is still
valid). The container could not refresh the token, which is
the expected FR-3 behavior.

This addendum supersedes the "container cannot refresh" claim in
`evidence/task-1.3-1.4-credential.txt` step 4: the container
now has a proven access path to the model endpoint with the
access-only credential. The refresh path remains unproven
without a prompt whose access token has expired (that is
post-Quota-Window testing, not Phase 1 work).

## 6. Free-model source

Model: `opencode-go/beam-free`.
Source for "free":

- `opencode models` (host, with the live fetch) lists it.
- The OpenCode Go plan (source `https://opencode.ai/docs/go/`)

  `opencode models` output)". The citation is `opencode models`
  output and the model name.

## 8. What this run proves (vs. what stays unproven)

Proven:
- The flags `--standalone`, `--format json`, `--auto`, and
  `--model` work as documented.
- `--auto` leaves no permission prompt (the config denies
  `question`, so even the default `build` agent's `ask` is
  short-circuited).
- stdin from `/dev/null` works (no interactive prompts).
- The JSON event stream is well-formed NDJSON with `type` fields.
- The access-only copy (inert refresh) is accepted by
  `opencode auth import` and the model call completes.
- The host's Console login is untouched.

Stays unproven (or proven elsewhere):
- Whether the inert refresh would block a real renewal when
  the access token expires (the O3 probe in task 1.8 used a
  valid access token; a renewal test needs a prompt after
  expiry, which is post-Quota-Window work).
- Whether `--auto` would work for agents that include a
  `read` permission for the workspace (it should, but the prompt
  here was trivial).
