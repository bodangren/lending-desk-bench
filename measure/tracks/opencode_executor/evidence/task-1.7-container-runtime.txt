## 2. Podman flags used (rootless)

```
--rm --pull=never
--tmpfs /tmp:rw,nosuid,nodev,noexec,size=512m
--cap-drop=ALL
--security-opt=no-new-privileges
--userns=keep-id
--user "$(id -u):$(id -g)"
--network slirp4netns:allow_host_loopback=false
--mount type=bind,src=.../opencode.exe,dst=/usr/local/bin/opencode,ro
--env HOME=/tmp/home
--env XDG_CONFIG_HOME=/tmp/config
--env XDG_DATA_HOME=/tmp/data
--env XDG_STATE_HOME=/tmp/state
--env XDG_CACHE_HOME=/tmp/cache
--workdir /tmp
```

HOME and XDG dirs point into the noexec /tmp tmpfs; they are
pre-created by the entry script so the service's chdir to HOME
succeeds. The opencode binary is the only host path mounted.
The image's standard root FS provides the exec surface; /tmp is
the only noexec mount and contains no executables we run.

## 4. Helper needs and the chosen supply method

### 4.1 ripgrep (rg) — required by the built-in `grep` tool

The opencode binary contains a built-in `grep` tool whose
description is, verbatim from the binary:

```
Search file contents using ripgrep's regular expression syntax or
literal text matching. Use it to locate specific code, symbols,
or text patterns, and narrow searches with `path` or `include`.
Returns matching file paths, line numbers, and line previews.
```

The binary's helper-resolution code (extracted from
`$bunfs/root/chunk-...js`) is:

```js
let O = N("rg");                          // PATH lookup
if (O && isFile(O)) return O;
let V = `${T.bin}/rg`;                    // cache bin lookup
if (isFile(V)) return V;
let K = `https://github.com/BurntSushi/ripgrep/releases/download/15.1.0/ripgrep-15.1.0-${D.platform}.${D.extension}`;
fetch(K).then(... writeFile(Y, bytes) ...);
spawnSync("tar", ["-xzf", Y, "-C", D], D);
copyFile(`${D}/ripgrep-15.1.0-${D.platform}/rg`, V);
chmod(V, 0o755);
```

URL: `https://github.com/BurntSushi/ripgrep/releases/download/15.1.0/`
Platform variant for this image: `x86_64-linux-musl`.

If the helper is absent AND the download fails, the `grep` tool
returns the error "ripgrep failed with code N" or
"ripgrep execution failed". The agent's own code/text search
breaks. Every model run that touches the workspace will trigger
this.

### 4.2 Formatters (prettier, eslint, biome) — run via `npx`

The binary references `prettier`, `eslint`, and `@biomejs/biome`
in 162 formatter-related matches. These are launched as
`npx <formatter>` and run under the image's `node` (v22.23.1).
No separate exec mount is required: the node binary in
`/usr/local/bin/` is on a regular exec mount.

### 4.3 Language servers — not used at container start-up

The `language server` substring appears twice in the binary and
references only the abstract concept in error/help text. No
download URL exists for any language server. The harness does
not need to supply one.

### 4.4 Chosen supply method: bind-mount a pre-shipped `rg` as `/usr/local/bin/rg`

**Method.** The harness copies a known-good `rg` binary
(ripgrep 15.1.0, x86_64-linux-musl) into the per-run artifact
tree, then Podman bind-mounts it read-only at
`/usr/local/bin/rg` inside the container:

```
--mount type=bind,src=$OUT/rg,dst=/usr/local/bin/rg,ro
```

The container's `/usr/local/bin/` is on the image's regular root
FS, which is exec. `/usr/local/bin/` is also on the opencode
PATH lookup, so the binary's `N("rg")` PATH check returns the
shipped `rg` on the very first call. The download-and-extract
fallback is never reached, so opencode never needs to reach
`github.com` at start-up, and the noexec `/tmp` constraint is
satisfied without a per-bucket exec mount.

**Why this and not the alternatives.**

- *Let opencode download into `<bin>/rg`*: this lands at
  `/tmp/cache/opencode/bin/rg`, which is inside the noexec
  `/tmp` tmpfs. The downloaded `rg` would not be executable.
  Mounting `/tmp/cache/opencode/bin` as a separate exec tmpfs
  works, but adds a second mount for one file and re-uses
  opencode's network path at every run.
- *Build ripgrep into the image*: requires a custom image
  fork; breaks `--pull=never` portability.
- *Skip ripgrep*: the `grep` tool then errors on every
  candidate's first workspace touch. The agent can still
  finish a tiny run, but the harness loses the FR-4 contract
  (the `grep` tool is part of the default `build` agent).

**Exec surface under the chosen method.**

- `/usr/local/bin/rg` — exec (image root FS).
- `/usr/local/bin/opencode` — exec (image root FS, read-only bind).
- `/tmp` — noexec. Contains only data files, sockets, and
  the opencode sqlite DB. No executables are run from `/tmp`.

## 6. Network endpoints at start-up

- `opencode --version`: 0 network. Succeeds under
  `--network=none` (T18, T27).
- `opencode debug paths`: 0 network. Succeeds under
  `--network=none`.
- `opencode mcp list` / `opencode plugin list`: 0 network. Run
  after pre-creating HOME (T12, T13).
- `opencode models`: 0 network. Lists 12 built-in
  `opencode/*` ids under `--network=none` (T32). The full
  `opencode-go/*` list is fetched from the live models endpoint
  only when `OPENCODE_DISABLE_MODELS_FETCH` is not set and the
  cache is empty; in the container the harness sets
  `OPENCODE_DISABLE_MODELS_FETCH=1` (strategy 4.2) and the
  binary's model catalog is enough for the executor
  preflight.
- `opencode stats`: 0 network. Reads the local sqlite store.
- The only network the binary can make is the
  `github.com/BurntSushi/ripgrep` fetch described in
  section 4.1. With the chosen supply method (pre-shipped
  `rg` on PATH) this code path is not taken.

| bind | `<nvm>/.../opencode.exe` | `/usr/local/bin/opencode` | yes | yes |

| tmpfs | — | `/tmp` (rw, nosuid, nodev, noexec, size=512m) | — | no |
| tmpfs | — | `/run/opencode` (rw, nosuid, nodev, size=64m) | — | no |

`/tmp/home`, `/tmp/config`, `/tmp/data`, `/tmp/state`,
`/tmp/cache` before the agent starts.

The harness's exit trap and the per-run artifact cleanup (NFR-1,
FR-8) already remove `$OUT`; the new `$OUT/rg` is removed at the
same time.
