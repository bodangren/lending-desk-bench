# Task 1.2 — Cron self-check root cause

R0 (the 2026-10-18 reproduction) ran the meta logic suite under the crontab
PATH. The three failing tests all read a 0-byte file the spawned
`grade.sh` left behind. The root cause is the snap dispatcher at
`/usr/bin/snap` (linked from `/snap/bin/node` and `/snap/bin/npm`):
when invoked from a bash that is a child of vitest's spawnSync, the
dispatcher returns success but produces no output. The nvm toolchain
is the fix.

## 4. Root cause of the 0-byte file

The exact call that produces 0 bytes is `npm run typecheck
> $OUT/typecheck.log 2>&1` from inside `grade.sh`, when the bash
is the spawnSync child of vitest.

Decisive checks (all run from inside vitest's spawnSync under
the crontab PATH):

```
direct /snap/bin/npm run typecheck                       (size 138)  OK
bash -c "...npm run typecheck > file 2>&1"               (size 0)    FAILS
bash -c "/snap/bin/node .../npm-cli.js run typecheck ..."
                                                        (size 48)  OK
bash -c "/snap/bin/node -e 'console.log(...)' > file"
                                                        (size 0)    FAILS
bash -c "/snap/node/12153/bin/node -e 'console.log(...)'
   > file"                                              (size 21)  OK
bash -c "/snap/node/12153/bin/node .../tsc --noEmit > f"
                                                        (size 90)  OK
```

The exact pattern: any call that goes through `/snap/bin/node`
or `/snap/bin/npm` (both are symlinks to `node.npm` or
`node.node`, which the snap dispatcher reads from `argv[0]`)
produces 0 bytes when invoked from a bash that is a child of
vitest's spawnSync. Calling the real ELF binary at
`/snap/node/12153/bin/node` directly works. `echo`, `cat`, and
`printf` redirects from bash also work.

The snap dispatcher at `/usr/bin/snap` reads `argv[0]` to pick
the snap app, then execs the snap's binary. The dispatcher
returns success (`rc=0`) but never writes to the redirected
file. This is the dispatcher failing in a non-tty, no-controlling-tty
context (vitest's child is detached). The bash redirect itself
works (`echo > file` from bash writes 22 bytes correctly).

The per-test timings of the 3 failing tests under cron PATH:
  exits nonzero when score.ts produces an invalid record   (11939ms)
  keeps a structurally valid gate-blocked record...        (7071ms)
  standalone grade rejects a protected candidate mutation   (1540ms)
None reached 60s. The per-test budget is not the trigger.
The vitest worker, the spawnSync call, and the bash redirect
all complete well under the budget. The child writes 0 bytes
to the redirected file before npm's "typecheck error" output
or any other output reaches the file. The harness then reads
the 0-byte file and JSON.parse fails.

## 5. Why the nvm toolchain fixes it

The nvm toolchain is at
`/home/daniebo/.nvm/versions/node/v24.19.0/bin/`. Each entry
(node, npm, npx) is a real ELF binary (or a symlink to a real
ELF binary in the same dir). No snap dispatcher. The
dispatcher is what breaks in the cron PATH; the nvm toolchain
does not use it.

Decisive check (under vitest's spawnSync, cron PATH with
`PATH=/home/daniebo/.nvm/versions/node/v24.19.0/bin:$PATH`):

```
bash -c "...PATH=nvm:$PATH node -e 'console.log(...)' > f"  (15)  OK
bash -c "...PATH=nvm:$PATH npm run typecheck > f"           (138) OK
bash -c "...PATH=nvm:$PATH npx tsc --noEmit > f"             (90) OK
```

All three write to the redirect. The nvm toolchain replaces
the snap dispatcher with a direct ELF binary and the cron
self-check passes.

## 6. Minimal fix (do not write; Phase 3 writes it)

The strategy fixes this in `harness/toolchain.sh`, which
`cron-weekly.sh` sources before `weekly.sh`. The toolchain file
makes `node`, `npm`, and `opencode` resolve to the operator's
nvm toolchain under cron. Under the nvm toolchain, the three
failing tests pass and the suite finishes green.

Strategy's REHEARSAL command (unchanged):

```
env -i HOME="$HOME" PATH=/snap/bin:/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin \
  bash -c 'set -eu; cd /home/daniebo/Desktop/lending-desk-bench/harness; . ./toolchain.sh; . ./env.sh; env -u BENCH_TRACK npm run --silent test:meta:logic'
```

The toolchain file name (`harness/toolchain.sh`) is the one in
strategy section 2. design.md does not need a different file.
