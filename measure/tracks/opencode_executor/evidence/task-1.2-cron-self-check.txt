## 3. Time limit that stops the child process

The Vitest test timeout is the 3rd argument to `it()`. All three failing
tests carry `}, 60_000);`:

  harness/tests/meta/runner-safety.test.ts:104
  harness/tests/meta/grade-exit.test.ts:51
  harness/tests/meta/grade-exit.test.ts:73

There is no `spawnSync` `timeout` option in the test. The harness calls
`spawnSync` without `timeout`, so the only ceiling is the Vitest test
timeout (60s). The test then relies on Node's child lifecycle; if Vitest
aborts the test, the spawned `grade.sh` and its `npm` / `tsx` / `next`
children are killed.

The suite total of 62.99s is just over the 60s budget. The 3 failing
tests' individual times (1.5s, 7s, 12s) are well under 60s, so the
timeout is not the direct cause of the empty files. The root cause is
elsewhere (see section 5).

## 4. Why `score.json` and `candidate-contract.json` end up empty

Direct reproduction (env: cron PATH, run from this host's shell):

  Command: `npm run typecheck > "$OUT/typecheck.log" 2>&1` from a sh
  child of vitest's spawnSync.

  Observation: typecheck.log size = 0 bytes. The `> typecheck.log 2>&1`
  shell redirect truncates the file to 0 bytes before `npm` runs. The
  same `npm run typecheck` invoked directly via vitest's `spawnSync`
  (without an intermediate sh) writes 138 bytes to the same target.

Diagnostic artifact (sizes captured immediately after a vitest
spawnSync of `grade.sh`):

  browser-check.log      0 bytes
  build.log              0 bytes
  candidate-contract.json 0 bytes
  collection.json       42 bytes  (printf inside grade.sh, no spawn)
  gate.json             34 bytes  (echo inside grade.sh, no spawn)
  score.json             0 bytes
  typecheck.log          0 bytes

The only files that end up non-empty are the two that the shell writes
synchronously with `printf` and `echo`. Every file that captures a
spawned child (`npm run typecheck`, `npm run build`, `tsx score.ts`,
`tsx candidate-contract.ts`) ends up at 0 bytes.

The shell's `> file 2>&1` redirect truncates the file first, then the
child writes (or is killed before it writes), so the file ends at 0 bytes.
`score.json` and `candidate-contract.json` are produced the same way:
the shell truncates them, then the `tsx` child writes (or doesn't),
leaving the file at 0 bytes when the test reads it.

## 5. Minimal fix (do not write; Phase 3 writes it)

The strategy fixes this in `harness/toolchain.sh`, which `cron-weekly.sh`
sources before `weekly.sh`. The toolchain file makes `node`, `npm`, and
`opencode` resolve to the operator's nvm toolchain under cron. Under the
nvm toolchain, the suite finishes in 58.84s (below the 60s test budget)
and the three failing tests pass.

Strategy's REHEARSAL command (also unchanged):

```
env -i HOME="$HOME" PATH=/snap/bin:/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin \
  bash -c 'set -eu; cd /home/daniebo/Desktop/lending-desk-bench/harness; . ./toolchain.sh; . ./env.sh; env -u BENCH_TRACK npm run --silent test:meta:logic'
```

The toolchain file name (`harness/toolchain.sh`) is the one in strategy
section 2. design.md does not need a different file.
