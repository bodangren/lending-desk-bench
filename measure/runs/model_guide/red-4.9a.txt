Token shape used (stated, per the PM order)
  The repo holds no parse code for the token fields, so the shape is the
  one the PM named. The fake emits one json event per call that holds
  tokens, in the shape of an `opencode run --format json` step-finish
  event:

    {"type":"step-finish","tokens":{"input":10,"output":20,"reasoning":5,
      "cache":{"read":100,"write":7}}}

  The record holds the flat sums of spec D13:

    "tokens": {"input","output","reasoning","cache_read","cache_write",
               "total"}

  `total` is the sum of the five components. Each entry of `diffs` holds
  its `id` and its own `tokens` object in the same shape. `tokens_complete`
  is `true` when every call held a token field and `false` when one call
  did not; a call with no token field adds 0.
